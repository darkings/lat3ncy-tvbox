# Ponyo TV 全页面视觉审计与深度美化方案

> 文档状态：实施主规范。统一交付入口见 [README.md](README.md)，可执行资料见 [materials/README.md](materials/README.md)。若与同目录补充分析稿存在冲突，以本文及 `materials` 中的机器可读规范为准。

审计日期：2026-08-10  
目标画布：1280 × 720 设计基准，主要验收设备为 1920 × 1080 TV  
审计范围：44 张 ADB 截图、11 个 Activity、4 个主要 Fragment、20 个具体 Dialog  
任务边界：只交付审计、规范和可用资料，不修改 Android App 代码

## 1. 结论

当前版本已经完成第一层品牌化：应用名称、暖色背景、珊瑚色焦点、品牌图标和角色动画都已进入界面。但它还没有形成完整的 TV 视觉系统。最明显的问题不是某一处“不够漂亮”，而是同一产品里同时存在多套视觉语言：

- 首页使用暖海色与圆角胶囊，详情页仍混用亮绿、玫红和旧蓝色按钮。
- 首页、搜索、设置、播放器分别使用不同的间距、圆角、图标和焦点表达。
- 海报上的评分、来源、更新、标题大量叠在画面上，内容可读性差。
- 设置页一次展示过多项目，没有分类标题、导航层级和滚动位置。
- 加载态大多只有一个白色旋转图标，无法告诉用户正在做什么、是否卡住、能否返回。
- 品牌角色在首页长期占据右下角并可能遮挡内容，播放器和直播也出现角色素材，削弱了影院内容的主角地位。
- 部分页面名称、截图内容和真实 Activity 不一致；若直接按文件名改版，会把加载页或错误跳转误判成业务页。

深度美化应把产品统一为“暖海夜航影院”：

1. 内容是第一主角，角色是有节制的向导。
2. 焦点在任何背景上都能一眼识别。
3. 信息分层清楚，首屏只展示决策所需内容。
4. 所有页面共用同一套颜色、字号、圆角、焦点、加载和弹窗规范。
5. TV 遥控器路径、远距离可读性和弱网状态优先于手机式装饰。

## 3. 品牌视觉系统

### 3.1 品牌定位

品牌关键词：

- 温暖：珊瑚、奶油、柔和圆角。
- 安静：深可可背景、大面积留白、低噪声表面。
- 可靠：明确的焦点、状态和操作反馈。
- 有陪伴感：角色只在启动、首页欢迎、空状态和错误恢复中出现。
- 影院感：海报、片名、进度和播放决策优先，避免儿童应用式满屏角色装饰。

### 3.2 色彩角色

正式 token 已交付为 [design-tokens.json](materials/design-tokens.json)，色板图为 [style-board.svg](materials/style-board.svg)。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| Background | #17120F | 全局底色、播放器外的页面底色 |
| Surface low | #201A16 | 低层容器 |
| Surface | #241E1A | 普通卡片、按钮、列表项 |
| Surface high | #2F2824 | 弹窗、设置面板、浮层 |
| Surface highest | #3A322E | 悬浮提示、重点信息块 |
| Primary | #F1A494 | 主操作、焦点描边、品牌强调 |
| Primary bright | #F8BBAE | 高亮焦点和小面积强调 |
| Primary container | #743B30 | 焦点填充、已选容器 |
| On primary container | #FFDBD2 | 焦点文字和图标 |
| Tertiary | #8FCFFC | 链接、信息提示、可选的技术状态 |
| Text primary | #F0DED9 | 主文字 |
| Text secondary | #D6C2BC | 元数据和次级说明 |
| Outline | #9F8B85 | 必要边界 |
| Outline subtle | #52433F | 非焦点边界 |
| Error | #FFB4AB | 错误和危险操作 |
| Scrim 60% | #99000000 | Dialog 和侧栏遮罩 |

必须删除或收口的旧色：

- 详情页简介按钮的荧光绿。
- 收藏按钮的高饱和玫红。
- 与品牌无关的亮蓝、荧光青和多色标签。
- 用颜色随机区分年份、地区、语言的做法。

颜色只能表达角色，不表达装饰。一个界面同时出现的强调色不超过两个：Primary 与 Tertiary。

### 3.3 字体与字号

当前项目启用了 AndroidAutoSize 的 MM 子单位，DP 和 SP 不参与 AutoSize。现有资源又混合 mm、dp、sp 和 px，导致不同 TV 密度下比例不稳定。实施时应把业务布局统一为 design-mm token；dp 只保留给系统组件兼容项，并逐步消除硬编码 px。

| Token | design-mm | 1080p 参考像素 | 用途 |
| --- | ---: | ---: | --- |
| Display | 40 | 60 | 启动页品牌、极少数大数字 |
| Page title | 34 | 51 | 历史、收藏、设置等页面标题 |
| Section title | 28 | 42 | 内容分区、Dialog 标题 |
| Title | 24 | 36 | 卡片标题、主要按钮 |
| Body | 22 | 33 | 正文、导航和常用操作 |
| Label | 20 | 30 | 标签、元数据、设置值 |
| Supporting | 18 | 27 | 次级说明 |
| Caption | 16 | 24 | 时间、计数、技术状态 |

规则：

- 正文最小 20 design-mm；16 只用于不承担决策的辅助信息。
- 海报标题最多两行；列表标题一行并使用尾部省略。
- URL、路径和来源名使用中间省略，不允许挤压相邻操作。
- 不再使用人为插入空格的“历  史”“更  多”等文本。
- 数字时间和进度可使用等宽数字，但不要让全局字体变成等宽字体。

### 3.4 栅格、留白和安全区

- 设计基准：1280 × 720。
- 1080p 缩放系数：1.5。
- 水平安全边距：64 design-mm，约 96 px。
- 垂直安全边距：32 design-mm，约 48 px。
- 基础间距：8 design-mm。
- 常用间距：8、12、16、24、32、48、64。
- 不允许关键文字、焦点描边和操作按钮进入安全区外。
- 页面根容器必须允许焦点元素放大而不裁切。
- 所有横向列表在右侧保留淡出或部分露出下一项，明确还有内容。

### 3.5 圆角与层级

| 组件 | 圆角 |
| --- | ---: |
| 小标签 | 8 design-mm |
| 海报卡 | 12 design-mm |
| 普通列表项和按钮 | 12 design-mm |
| 面板 | 16 design-mm |
| 大 Dialog | 24 design-mm |
| 胶囊导航和筛选 chip | Full |

TV 上不依赖真实阴影建立层级，优先使用色调层级、描边和 scrim。播放器浮层允许使用黑色渐变，因为它覆盖视频内容。

## 4. 遥控器焦点系统

当前焦点虽然使用珊瑚填充和描边，但“已选”“焦点”“按下”“禁用”没有完整区分。统一规则如下：

| 状态 | 视觉 |
| --- | --- |
| Default | Surface 填充，1 design-mm Outline subtle |
| Selected | Primary container 32% 色调或左侧品牌条，不放大 |
| Focused | Primary container 填充，3 design-mm Primary bright 外环，1.06 倍缩放 |
| Selected + Focused | Focused 外环，加选中标记或品牌条 |
| Pressed | 缩放回 1.00，亮度降低 6%，80 ms |
| Disabled | 38% 文字，12% 容器，不可获得焦点 |
| Destructive focused | Error container 填充和 Error 外环 |

硬性要求：

- 焦点反馈在 150 ms 内完成。
- 焦点环不能被父容器裁切。
- 同一屏只能有一个主焦点。
- 返回页面时恢复离开前焦点；数据刷新后尽量保持原索引。
- 上下左右均不能进入无响应区域或形成不可退出的焦点环。
- 图标按钮必须有文字标签、可读的 contentDescription，或在焦点时显示说明。
- “删除”“清空”等危险操作不能用两个相似的无文字图标并排表达。

## 5. 状态、加载与动效

### 5.1 加载状态

当前白色旋转箭头容易被理解为“刷新”，也没有上下文。统一为三阶段：

1. 0 至 300 ms：不显示加载，避免快速切换闪烁。
2. 300 ms 至 3 s：显示小型进度动效和动作文本，例如“正在读取首页内容”。
3. 3 s 以后：增加次级说明，例如“网络较慢，仍在尝试”；必须允许返回。

加载失败必须出现：

- 明确标题。
- 一句可理解的原因。
- 主操作“重试”。
- 次操作“返回”或“更换来源”。
- 技术错误只放在可展开详情中。

所有正式文案已交付为 [copy-deck.json](materials/copy-deck.json)。

### 5.2 品牌角色

现有 8 × 9 角色图集可保留，但必须限制使用场景：

- 启动：WAVING 播放一次，随后静止。
- 首页首次完成加载：WAVING 播放一次。
- 等待超过 3 s：WAITING。
- 空收藏、空历史：IDLE 或 WAVING。
- 可恢复错误：FAILED 播放一次，随后 WAITING。
- 播放器、直播画面、设置密集页面和所有普通海报列表：不显示角色。

首页右下角长期显示 120 × 130 的角色会遮挡网格，应改为保留区域内 72 至 88 design-mm，或只在状态切换时短暂出现。角色不能被当作直播频道台标或视频占位图。

图集行、帧数和时序已交付为 [motion-spec.json](materials/motion-spec.json)。

### 5.3 通用动效

- 焦点进入：120 ms，强调减速曲线。
- Tab 指示器：160 ms。
- Dialog 进入：180 ms；退出：140 ms。
- 页面交叉淡化：220 ms。
- 侧栏滑入：220 ms。
- Snackbar 或换台提示：停留 1800 ms。
- 骨架呼吸：1200 ms，透明度 0.55 至 0.78。
- 所有常驻动画必须在页面不可见时停止。
- 提供减少动态效果模式：禁用缩放和角色逐帧动画，只保留 80 ms 颜色过渡。

## 6. 分页面改造

### 6.1 SplashActivity

截图证据：

- 39、40 是模拟器桌面，不能用于 App 样式判断。
- 41、42 是相同的系统启动预览，仅显示大号角色图标。
- 当前存在“浅色系统预览 → 深色首页加载”的明显视觉断层。
- activity_splash.xml 定义了图标、Ponyo TV 和“专属电视影院”，但截图只捕获到系统预览，说明两段启动视觉没有形成稳定连续体验。

改造：

- 系统 window background 与 Activity 首帧使用完全一致的暖奶油渐变。
- 中心使用 160 至 180 design-mm 的品牌图标，右侧或下方显示 Ponyo TV。
- 副标题改为“今晚，选一部好片”，比“专属电视影院”更自然。
- Splash 总时长控制在 700 至 900 ms；初始化未完成时不要无限停留在浅色画面，切入深色 App Shell 并显示带文案加载态。
- 只播放一次轻微呼吸或挥手，不使用旋转。
- 转场结束后焦点直接落到首页恢复项或默认主入口。

可用素材：

- app_icon 各密度图。
- ponyo_icon.png。
- app_banner.png。
- ponyo_splash_background.xml 与 ponyo_splash_window.xml。
- 角色图集 ponyo_spritesheet.webp。

实际路径见 [brand-assets.md](materials/brand-assets.md)。

### 6.2 HomeActivity 与 UserFragment

截图证据：

- 04、16、23、24 展示了完整首页。
- 03、19-首页-内容焦点、34 展示了首页来源选择 Dialog。
- 01、02、13、14、15、43 实际上主要是首页加载态。
- 顶部分类在 1920 宽度下仍被右侧裁切，没有明确的继续滚动提示。
- 功能按钮与分类、品牌、时间、海报同时争夺注意力。
- 海报上同时显示评分、说明、标题，文字覆盖画面。
- 右下角角色过大，在多行网格中会遮挡海报。

目标结构：

1. 品牌栏：图标、Ponyo TV、当前来源，右侧为日期和时间。
2. 分类栏：水平 Tab；只显示分类，不混入工具入口。
3. 快捷操作：继续观看、搜索、直播、收藏；设置与推送放入“更多”。
4. 内容区：继续观看横向行或 5 列海报网格。
5. 状态角色：仅在空白、加载完成和错误时出现，不常驻覆盖内容。

元素级修改：

- 品牌图标缩至 32 至 36 design-mm，Ponyo TV 使用 Title 字号。
- 当前来源作为可聚焦 chip，显示来源名与下拉箭头；不要把“Ponyo TV · 来源名”写成一长串标题。
- 日期时间使用 Caption，不需要独立大胶囊背景。
- 分类 Tab 高度 44 至 48 design-mm，当前选中用底部 3 design-mm 指示器；焦点再加外环。
- 分类栏右侧保留 32 design-mm 渐隐，并露出下一项 20%。
- 快捷按钮高度 52 至 56 design-mm，图标 24，文字 22；同一行最多五个。
- “推送”改名“手机推送”；收藏使用“收藏”，不在同一入口同时使用“收藏夹”。
- 海报统一 2:3，建议 200 × 300 design-mm；1080p 显示约 300 × 450 px。
- 海报卡只保留：左上质量或来源一个 badge、右上评分、底部标题。更新说明放进详情页。
- 焦点海报放大 1.06，底部显示片名、年份、类型的扩展信息条，不把更多文字叠在海报中间。
- 首页内容没有数据时显示“当前来源暂无推荐”，提供“更换来源”和“搜索”。

来源选择 Dialog：

- 标题改为“选择首页来源”，副标题显示当前来源和来源总数。
- “配置中心”“本地视频”放在独立的工具区，不与内容源混排。
- 内容源每项显示名称、类型和可用状态；长名称最多两行。
- 每行三列，行高 64，焦点按视觉顺序移动。
- 当前来源使用 Selected 状态；焦点和已选状态必须可同时识别。
- 右上角显示关闭提示，返回键可关闭并恢复原焦点。

### 6.3 GridFragment、分类和筛选

截图证据：

- 05 是有效的豆瓣内容网格。
- 当前五列海报视觉冲击强，但海报比例偏宽，底部第三行被截在屏幕边缘。
- 评分和榜单文案共用一个灰底标签，长文本遮住海报。
- 真正的 GridFilterDialog 未得到可靠截图。

目标结构：

- 顶部保留分类标题、结果数和筛选按钮。
- 内容区使用 5 列 2:3 海报卡；上下保留完整焦点放大空间。
- 页面首次进入时焦点落在首个内容，不强制先经过筛选。
- 筛选按钮显示是否激活，例如“筛选 · 3”。

海报卡：

- 评分只显示数字，例如 7.6。
- 榜单来源或更新状态缩成一个短 badge，不拼在评分后。
- 标题最多两行，底部渐变高度不超过海报的 24%。
- 图片缺失时使用中性电影图标和片名首字，不使用品牌角色。
- 加载时使用与海报同尺寸的骨架卡，布局不跳动。

筛选：

- 推荐使用顶部下拉面板或右侧 Sheet，不覆盖整个内容上下文。
- 每组显示“类型、地区、年份、语言、排序”标题。
- 已选值使用 Selected 状态，遥控器焦点使用 Focused 状态。
- 底部固定“重置”和“应用”两个操作；筛选即时生效时仍提供“清除全部”。
- Filter Dialog 的 enter/exit 动效保持 180/140 ms。

### 6.4 DetailActivity

截图证据：

- 07 至 11 是同一详情页在不同加载时刻或来源状态下的有效截图。
- 左侧预览区域长时间为黑色加旋转图标。
- 右侧直接显示来源、年份、地区、语言、演员、导演、播放 URL 和长简介，信息密度过高。
- “全屏、快速搜索、简介、加入收藏”分别使用粉、粉、绿、玫红，多色不属于同一品牌系统。
- 页面下半部分大量空白，线路和选集层级不清楚。
- 29 是完全空的 DetailActivity 初始态。

目标结构：

- 上半区采用 5:7 栅格。左侧为海报或静音预览，右侧为标题、元数据、简介与操作。
- 标题使用 Page title；元数据合并为一行短 chip。
- 演员和导演最多各一行，完整内容通过“查看简介”打开。
- 原始播放 URL 默认隐藏，放入“技术信息”或调试模式。
- 主操作为“播放”或“继续播放”，只使用 Primary。
- 次操作为“选集与线路”“快速搜索”“收藏”，使用 Surface。
- “全屏”不是详情页主操作，应改成“播放”；预览区域可用确定键进入全屏。
- 下半区依次显示线路 Tab、分组/排序、选集网格。

线路与选集：

- 线路项显示名称、可用状态和最近成功信息，不使用难懂的短码作为唯一标签。
- 选中线路与焦点线路视觉分离。
- 选集按钮最小 96 × 48 design-mm。
- 大量选集按“1–50、51–100”分组，排序按钮固定在组标题旁。
- 已看集显示进度条或勾选，不只改变文字颜色。
- 无播放数据时显示“当前来源没有可播放线路”，提供“快速搜索”和“返回详情”。

预览：

- 默认静音，显示“预览”标签。
- 300 ms 后才显示加载；3 s 后显示说明。
- 预览失败不能让整个详情页失败，回退到海报。
- 焦点进入预览时出现边框和“确定键全屏”提示。

### 6.5 点播播放器与 PlayFragment

截图证据：

- 12 是播放器控制层，视频仍处于 0 × 0、0 bps 和 00:00。
- 一整排“下一集、上一集、重播、刷新、默认、EXO播放器、字幕、音轨、屏显”同时出现，主次不清。
- 左右返回与锁定图标距离内容很远，缺少焦点说明。
- 成功播放、暂停、拖动、字幕、弹幕和错误状态均未获得可靠截图。

目标控制层：

1. 顶层：片名、集数，右侧只在有效时显示清晰度、网络速度和系统时间。
2. 中层：缓冲、错误、暂停或快进反馈。
3. 底层第一行：当前时间、进度条、总时长。
4. 底层第二行：播放/暂停、上一集、下一集、选集、倍速、字幕、更多。

规则：

- 0 × 0、0 bps、00:00 等无效技术值不显示。
- “重播”和“刷新”放入更多菜单，发生错误时再提升为主操作。
- “默认”“EXO播放器”“IJK”等技术选项放入播放器设置 Sheet。
- 图标与文字组合，焦点时显示完整说明。
- 控制层使用黑色到透明渐变，不使用全宽实色深棕块遮挡视频。
- 进度条焦点高度放大，拖动时在焦点上方显示目标时间和预览图；无预览图时只显示时间。
- 锁定后仅保留 2 s 的解锁提示，长按确定键解锁。
- 返回键优先关闭当前 Sheet，再关闭控制层，最后退出播放。

错误态：

- 标题“暂时无法播放”。
- 正文按原因区分“线路失效、解析失败、网络中断、格式不支持”。
- 主操作“换一条线路”或“重试”。
- 次操作“返回详情”。
- 技术信息默认折叠。

### 6.14 Dialog 系统

当前代码包含 20 个具体 Dialog，可归并成五种样式：

1. 选择类：Select、ApiHistory、SearchRemoteTv、SearchCheckbox、GridFilter。
2. 表单类：Api、DanmuApi、LivePassword、SearchSubtitle。
3. 确认/信息类：Tip、ConfirmClear、Desc、About、XWalkInit。
4. 媒体设置类：Subtitle、DanmuSetting、CastDevice、QuickSearch。

统一规格：

- 普通 Dialog 宽 720 至 880 design-mm，最大高度 600。
- 标题区 72 高，内容区可滚动，底部操作区 72 高。

- [style-board.svg](materials/style-board.svg) 与 [style-board.png](materials/style-board.png)：可编辑矢量板和实际渲染预览。
- [copy-deck.json](materials/copy-deck.json)：全页面状态、主要操作和 20 个具体 Dialog 的正式文案。
- [motion-spec.json](materials/motion-spec.json)：页面、焦点、Dialog 和角色动效。
- [screen-coverage.csv](materials/screen-coverage.csv)：44 张截图逐张判定。
- [resource-map.tsv](materials/resource-map.tsv)：页面到布局、组件和资源的映射。
- [brand-assets.md](materials/brand-assets.md)：品牌图、角色、图标和字体素材清单及使用限制。
- [qa-checklist.md](materials/qa-checklist.md)：实施和截图验收清单。
- [tools/md3_res/README.md](../../../tools/md3_res/README.md)：80 个现有 XML、图标、字体和生成脚本，以及 Material Symbols 随包许可证的使用说明。

若实施阶段新增本方案未提到的插画、字体、音效或图标，应先补入 brand-assets.md 并确认来源与授权，再进入 APK。
